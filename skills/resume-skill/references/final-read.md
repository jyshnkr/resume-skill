# Final read (12 items, never blocks)

Run this after the edits pass `check.py` and before the reply. It lists what a script cannot judge. Nothing here stops a build; it only tells the user what to glance at.

Say in the reply: "Final read: I checked 4, you glance at 8", then list them in two groups.

## The model answers (4)
1. **Posting keywords** (rule 28): list the skill words the posting names twice or more and mark each as in the resume, true but not written, not yours, or unknown.
2. **Slop that needs context** (rules 18, 19): puffery or metaphor the word list cannot judge, such as a figurative "landscape".
3. **Duty or outcome** (rules 1, 67): for each reworded or new-to-this-resume bullet, say whether it states an outcome or only a duty ("so what?").
4. **Generic line** (rule 19): any line that would fit any candidate at any company.

## The user glances (8)
5. Each reworded bullet can be explained in an interview without backtracking (rule 45).
6. The draft sounds like the user's own writing (rule 21).
7. A recruiter's likely doubts are each answered by a real bullet near the top (rule 43).
8. If lines were cut, the posting's least-relevant line went first and no cut line leaves the resume misleading (rule 42).
9. Each posting term used means the same work at the same scope (rule 44).
10. The business domain is named in each role (rule 36).
11. The top third reads clearly in six seconds.
12. Optional: read it as a hiring manager would, in a fresh session.
